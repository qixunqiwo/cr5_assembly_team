# 五臂协同装配 — 交接说明

> 写于 2026-08-09，给接下来接手这条产线的同学。
> 一句话概括：五台 CR5A 现在能**并行抓取、按事件接力装配、锁付、分拣**，跑完一轮各回等待点，可以连续生产。

---

## 1. 这条产线现在能干什么

整条装配链已经串起来跑通：

```text
R4/R5 先到等待点站位
R1/R2/R3 同时下降抓取（箱体 / PCB / 控制模块）
  ↓
R1 放箱体（走中间点2 → 中间点1，不挡 R2 的路）
  ↓
R2 放 PCB（R1 此时去抓端子，两不耽误）
  ↓
R1 装端子（松开夹爪，端子自己落进标准位）
  ↓
R3 放控制模块（同样松开夹爪落下安装）
  ↓
组装完成 → 成品显示、零件隐藏 → R3 把成品搬到检测区
  ↓
R4 锁付（螺丝刀压住螺钉 1 秒）
  ↓
R5 分拣到 GOOD 传送带，产品沿传送带运走
  ↓
五臂各自回到等待点，准备下一轮
```

核心机制一句话：**所有臂在同一个仿真步进里推进（真正并行），段与段之间用事件接力（谁干完了谁放信号），没轮到的臂在等待点保持姿态不挡路。**

碰撞是每帧检测过的——十对臂两两组合，全程 0 碰撞。

## 2. 怎么跑起来看效果

前提：CoppeliaSim 已打开并加载 `scenes/compact_cell.ttt`。

**看单臂**（想单独调某台臂时）：

```bash
python3 scripts/r1_demo_flow.py   # R1：箱体 + 端子
python3 scripts/r2_demo_flow.py   # R2：PCB
python3 scripts/r3_demo_flow.py   # R3：模块 + 成品转运
python3 scripts/r4_demo_flow.py   # R4：锁付
python3 scripts/r5_demo_flow.py   # R5：分拣
```

**看五臂全流程**：

```bash
python3 scripts/coordinated_front.py
```

第一轮从 home 出发；如果上一轮已经跑完（各臂停在等待点），续跑下一轮：

```bash
python3 scripts/coordinated_front.py --start-from-wait
```

**从团队 app 触发**：app 连接场景后，任意 A/B/C 订单点 START，订单的第一个装配任务会自动触发五臂协调（在 `SimulationCellExecutor` 里做了映射），后面的任务直接标记完成——因为一轮协调已经把整条线都干完了。

## 新的东西怎么用

**新方案 = 预录路径 + 回放/协调控制器**，全部在 `robot_control/`：

**单臂流程**（想单独控制一台臂）：
```python
from sim_bridge.coppelia_client import SimBridge
from robot_control.replay_controller import ReplayController

bridge = SimBridge(); bridge.connect()      # 场景已打开
ctl = ReplayController(bridge, "R3")        # 换成 R1/R2/R3/R4/R5

pts = ctl.load("r3_module_pick_descend")    # 加载某段预录路径
ctl.replay(pts)                              # 正走
ctl.replay(pts, reverse=True)                # 反走（抬升/退出）
ctl.gripper(0.080)                           # 夹爪开度（平行爪）
ctl.attach("CONTROL_MODULE_SUPPLY")          # 抓工件
ctl.detach(handle)                           # 放工件
```

**五臂完整协调**（一次跑完整条产线）：
```python
from robot_control.coordinated_engine import CoordinatedEngine
engine = CoordinatedEngine()
engine.run_cycle()                           # 完整协调，阻塞至完成
engine.get_status()                          # 查询状态
```

命令行的更快方式：`python3 scripts/coordinated_front.py`（演示脚本，内部就是协调引擎）。

路径数据是这套东西的"大脑"：姿态在 `*_key_poses.json` 里定义，改姿态改这里，然后用 `replan_robot.py` 重新生成段路径。

## 4. 想改点什么，从哪下手

- **改某段路径的端点姿态**：编辑对应 `r*_key_poses.json` → 跑 `python3 scripts/replan_robot.py r3`（r3 换成对应臂）重新规划
- **某段 moveit 规划不了**：用 simIK 逐点生成（看 `r3_product_pick_descend` 的生成方式），不要硬磕 moveit
- **调 R3 夹爪朝向**（pad 连线垂直前后壁）：`python3 scripts/r3_j6_jog.py`，键盘 1/2/3/4 微调 j6，找到合适的角度后写回 key_poses
- **想加等待/事件**：在 `coordinated_front.py` 的 `handle_end` 里加，事件用 `fire("事件名")`，等待用 `arm.wait_event = "事件名"`

---

## 5. 踩过的坑（重要）

- **moveit 服务没响应，先查 move_group 进程**。它挂了的话所有规划都报 FAIL，但跟姿态没关系。重启：`ros2 launch cr5_moveit dobot_moveit.launch.py`
- **段间"闪回"**：绝大多数是"某段的起点写成了上一段的低位端点，而不是抬升后的位置"。改段起点后一定重规划。
- **场景指纹**：改过场景文件（保存/删物件）后，`configs/scene_contract.yaml` 和 `robot_control/plans/*.json` 里的 scene_fingerprint 都要同步，否则 preflight 报 size differs。
- **物料方向**：协调脚本每轮开头会重置物料位置和方向（箱体 yaw 180 那套是踩过坑调出来的，别乱改）。
- **组装件隐藏**：R3 抓成品前零件会被隐藏（箱体/PCB/模块/端子），成品显示——这是故意设计的，下一轮开头会自动恢复。
