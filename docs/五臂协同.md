# 五臂协同

## 1. 项目概述

本项目实现五台 CR5A 机械臂的协同装配仿真（CoppeliaSim 场景 `scenes/compact_cell.ttt`）。五台机械臂通过预录路径与事件驱动的方式，完成一条完整的电控箱装配线：

```
R4 / R5 先到等待点站位
R1 / R2 / R3 并行下降抓取（箱体 / PCB / 控制模块）
  ↓
R1 放箱体 → R2 放 PCB → R1 装端子（松开夹爪落下安装）
  ↓
R3 放控制模块（松开夹爪落下安装）→ 成品显示、零件隐藏
  ↓
R3 搬运成品到检测区 → R4 锁付 → R5 分拣到 GOOD 传送带
  ↓
五臂回到各自等待点，准备下一轮
```

所有机械臂在同一仿真步进中推进（真并行），段与段之间以事件接力，等待中的机械臂在等待点保持姿态。全程碰撞检测为零。

## 2. 系统结构

```
robot_control/                    核心代码（新方案）
├── coordinated_engine.py         五臂协调引擎：完整流程 + 状态查询
├── replay_controller.py          单臂回放控制器：预录路径驱动单台机械臂
├── simulation_executor.py        app 接入层：COORDINATED_CYCLE 任务触发协调
└── robot_executor.py             注册 COORDINATED_CYCLE 动作

scripts/                          可运行脚本
├── coordinated_front.py          五臂协调执行脚本（引擎底层）
├── r1_demo_flow.py ~ r4_demo_flow.py   单臂演示
├── replan_robot.py               按关键姿态重规划某臂全部段
└── r3_j6_jog.py                  键盘微调 R3 第六关节

data/captured_paths/              路径数据（核心资产）
├── r1_key_poses.json ~ r5_key_poses.json   各臂关键姿态与段定义
└── r1_*.json ~ r5_*.json         各段预录关节路径（moveit / simIK 生成）
```

> 说明：`robot_control/r1_motion.py ~ r5_motion.py` 为原串行控制器，保留但新方案不使用。

## 3. 环境准备

- Ubuntu 22.04 + ROS2 Humble + CoppeliaSim Edu V4.10.0
- 启动仿真：`cd ~/桌面/cr5_assembly_team && ~/CoppeliaSim/coppeliaSim.sh scenes/compact_cell.ttt`
- 规划工具需要 move_group 运行：`ros2 launch cr5_moveit dobot_moveit.launch.py`（仅重规划路径时需要）

## 4. 使用说明

### 4.1 运行五臂完整协调

**命令行（终端直接运行）：**

```bash
cd ~/桌面/cr5_assembly_team && python3 scripts/coordinated_front.py
```

- 第一轮从 home 出发
- 上一轮已结束、机械臂在等待点时续跑：`python3 scripts/coordinated_front.py --start-from-wait`

**代码调用（app / 调度系统）：**

```python
from robot_control.coordinated_engine import CoordinatedEngine

engine = CoordinatedEngine()
engine.run_cycle()                 # 完整协调，阻塞至完成
engine.get_status()                # 查询状态（idle / running / 最近阶段）
engine.get_robot_states()          # 五臂当前关节角
engine.load_key_poses()            # 加载各臂关键姿态
```

> `CoordinatedEngine` 与 `coordinated_front.py` 是同一流程的两个入口：
> - **`coordinated_front.py`**：命令行入口，终端直接运行（演示 / 调试）
> - **`CoordinatedEngine`**：程序调用入口，供 app / 调度系统触发协调、查询状态
>
> `CoordinatedEngine.run_cycle()` 内部即执行 `coordinated_front.py` 的流程。日常终端操作用前者，程序集成用后者。

### 4.2 运行单臂流程

**使用 ReplayController（推荐，编程方式）：**

```python
from sim_bridge.coppelia_client import SimBridge
from robot_control.replay_controller import ReplayController

bridge = SimBridge()
bridge.connect()                    # 场景已打开
ctl = ReplayController(bridge, "R3")   # R1 / R2 / R3 / R4 / R5

pts = ctl.load("r3_module_pick_descend")    # 加载预录段
ctl.replay(pts)                          # 正走
ctl.replay(pts, reverse=True)            # 反走（抬升 / 退出）
ctl.gripper(0.080)                       # 夹爪开度（平行爪）
ctl.attach("CONTROL_MODULE_SUPPLY")      # 抓取工件
ctl.detach(handle)                       # 释放工件
ctl.to_pose(deg)                         # 直接设置关节角
ctl.run_flow([("段名", 1), ("段名", -1)])  # 按顺序回放多段
ctl.reset_to_home()                      # 回零位
```

**使用演示脚本（快速查看效果）：**

```bash
python3 scripts/r1_demo_flow.py   # R1：箱体 + 端子
python3 scripts/r2_demo_flow.py   # R2：PCB
python3 scripts/r3_demo_flow.py   # R3：控制模块 + 成品转运
python3 scripts/r4_demo_flow.py   # R4：锁付
```

### 4.3 与团队 app 集成

app 连接场景后，任意 A/B/C 订单点 START 即可触发五臂协调：订单的第一个装配任务（box_feed）自动映射为 `COORDINATED_CYCLE`，协调完成后其余任务直接标记完成。

## 5. 路径数据说明

路径数据是整套系统的核心，全部位于 `data/captured_paths/`：

- **`r*_key_poses.json`**：每台臂的关键姿态（抓取位、放置位、等待点、中间点）与段定义（每段的起点/终点姿态）。修改姿态时编辑此文件。
- **`r*_<段名>.json`**：每段的关节角轨迹（moveit 规划或 simIK 生成）。

修改姿态后需重新生成路径：

```bash
python3 scripts/replan_robot.py r3   # r3 换成对应臂，按 key_poses 重规划全部段
```

若某段 moveit 无法规划（个别姿态组合），改用 simIK 逐点生成（参照 `r3_product_pick_descend` 的生成方式）。

## 6. 接口一览

### CoordinatedEngine（robot_control/coordinated_engine.py）

| 方法 | 说明 |
|---|---|
| `run_cycle(quality="good", start_from_wait=False, timeout_s=600)` | 运行一轮完整协调，返回状态字典 |
| `get_status()` | 查询是否在运行 / 最近结果 |
| `get_robot_states()` | 五臂当前关节角（度） |
| `load_key_poses()` | 加载五臂关键姿态定义 |

### ReplayController（robot_control/replay_controller.py）

| 方法 | 说明 |
|---|---|
| `load(name)` | 加载预录段（关节角序列） |
| `load_pose(key)` | 从 key_poses 读关键姿态 |
| `replay(pts, reverse=False, max_step_deg=5.0)` | 回放一段路径 |
| `to_pose(deg)` | 直接设置关节角 |
| `run_flow(flow, on_segment_end=None)` | 按流程顺序回放多段 |
| `gripper(gap_m)` | 设置夹爪开度 |
| `attach(object_name)` / `detach(handle)` | 抓取 / 释放工件 |
| `place_material(name, position, yaw_deg, visible)` | 复位物料（位置/方向/可见性） |
| `reset_to_home()` / `restore_maxvel()` | 回零位 / 恢复关节速度限制 |

## 7. 关键点

- 段之间衔接：每段 `pts[0]` 等于段起点、`pts[-1]` 等于段终点，相邻段首尾一致；反走段（抬升/退出）终点为上一段的 app 位
- moveit 服务不可用时，检查 move_group 进程（`ps aux | grep move_group`），重启：`ros2 launch cr5_moveit dobot_moveit.launch.py`
- 场景文件改动后需同步 `configs/scene_contract.yaml` 与 `robot_control/plans/*.json` 中的场景指纹，否则 preflight 校验失败
